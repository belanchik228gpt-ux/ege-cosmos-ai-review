# Последовательный учебный диалог

Ориентир — предоставленный учеником диалог Astra про корень из квадрата и модуль. Переносится способ объяснения, а не фиксированные ответы на одну задачу.

1. Сначала преподаватель называет цель и составляет короткий план из смысловых частей. Исходное домашнее задание отделяется от учебного примера.
2. Один ответ объясняет одну законченную мысль: зачем действие нужно, как оно работает, небольшой пример и посильная попытка ученика. Длина определяется смыслом; череда односложных вопросов не заменяет объяснение.
3. При затруднении преподаватель выделяет правильную часть ответа и конкретное непонимание. Например, различает поиск неизвестного в уравнении и переписывание выражения. Для объяснения возвращается к числам, сохраняя прерванный пункт плана.
4. После уточнения преподаватель явно возвращается к прежнему плану. При смене метода, например на дискриминант, объясняет изменение. Равносильные записи принимаются без требования переписать ответ по шаблону.
5. Практика начинается после объяснения метода. Запрошенные пять упражнений предлагаются по одному с номером; готовое решение не заменяет самостоятельную попытку.
6. Итог различает разобранное вместе и выполненное самостоятельно. Завершение пункта плана не означает освоения темы.

## Состояние диалога

Каждый учебный ответ может содержать проверяемый `learningStep`: текущая задача, действие ученика, причина действия, фактический краткий итог, постоянные ID пунктов плана и накопленная память только этого занятия. Невалидные поля отбрасываются целиком; формулы не обрезаются. Старые диалоги без этого поля продолжают работать и получают план при следующем содержательном ответе.

Компактная карточка показывает текущий пункт и раскрывает весь план. Основной математический лист следует текущей задаче и действию; исходное условие и прошлые черновики доступны отдельно. Ключ черновика зависит от занятия, пункта, задачи и действия; уточнение причины не стирает рисунок.

Ответ, отклонённый арифметической сверкой, не подменяет план и не попадает в следующий запрос как достоверное объяснение. История пользователя сохраняется. Сверка покрывает поддерживаемые явные утверждения, а не доказывает правильность всех рассуждений модели.

## Приёмка

Проверяем настоящими ответами в EXE: наличие плана, сохранение его ID после уточнения, объяснение конкретного непонимания, смену задания над листом, восстановление после запуска и правильное принятие корней с индексами. Проверка интерфейса включает реальные screenshots. Unit-тесты дополняют эту приёмку, но не заменяют её и не гарантируют одинаковое качество всех будущих ответов.
