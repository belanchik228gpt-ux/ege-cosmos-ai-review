# Проверяемые шаги своей задачи

`problem-teaching.ts` строит `Task.teachingSteps` из проверенного `ProblemSpec`. Параметры и окончательный ответ поступают из локального математического парсера; модель не создаёт эталоны. `ProblemSession` хранит `teaching?: TeachingState`, а виртуальный `Session` позволяет использовать общий `getTeachingContext`, `handleTeachingTurn`, `selectTeachingStep` и hydrator без смешивания с историей предметных занятий.

Поддерживаемые локальные ветки: ряды и действие для площади прямоугольника; высота и половина произведения для треугольника; целое и сотая доля для процентов; центр, расстояние и направление для модуля; равенство, коэффициенты и дискриминант для уравнений; смысл долей, общие знаменатели и вычислительные действия для арифметики. Неподдерживаемое условие не получает выдуманный учебный разбор.

Промежуточные попытки остаются в `TeachingState.attempts`. Они не увеличивают счётчик попыток всей задачи и не объявляют её решённой. Итоговые ответы, включая последний завершающий шаг, перепроверяются `checkProblemAnswer`. После верного последнего шага кнопка «Далее» завершает задачу, если все обязательные шаги приняты и нет пропущенных. Перепечатывать принятый итог не нужно. Повтор не добавляет вторую попытку. Решение после подсказок отмечается выполненным с помощью; чтение готового ответа не выдаётся за самостоятельное решение.

При восстановлении сохраняются только допустимые ссылки на шаги данного условия и журнал попыток. Вопросы, визуальные числа и эталоны снова строятся из подтверждённого текста. Другой task ID не переносит активный шаг; произвольное сохранённое поле `answer` не становится ключом проверки. Подтверждённая учеником расшифровка фото проходит тот же путь, что текстовое условие.

`ProblemWorkspace` отображает единственный активный вопрос и `TeachingScene` на шагах помощи; исходное условие доступно рядом. На основном вопросе работает `ProblemScene`. Геометрические промежуточные сцены в этой версии используют анимированную запись с фактическими сторонами и формулой; новые геометрические варианты `TeachingVisual` не добавлены. Полная геометрическая сцена остаётся доступна на основном вопросе. Это ограничение визуальной детализации, а не новая возможность модели.

Перед модельным ожиданием локальный шаг уже записан и доступен. Специфическое затруднение может вызвать `planTutorTurn` с разрешёнными ID. Затем `getTutorResponse` получает только текущее разрешённое объяснение и вопрос через `teaching`, а полный исходный `Task` используется исключительно для защиты от преждевременного раскрытия ответа. Ответ модели применяется лишь к прежней ревизии активного шага. Отмена не удаляет локальный разбор. Шаги, проверка ответа и «Далее» не требуют модели.
