# Диагностика паузы настоящей модельной сцены

8 сентября 2026. Повторно открыт настоящий EXE с `app.asar` SHA-256 `0285dddca93a3c5c937605dabe579d792ce06d80f3ff4c9cd7e6ea0fb98cb37a`, ранее созданным изолированным профилем `studio-live-native-1788894342050` и сохранённым разговором. Новых запросов к модели, внедрения состояния или ответов не было.

Проверялась последняя настоящая сцена «Первый шаг: расстояние до нуля» из ответов OpenAI. Две последовательности replay → ожидание 500 мс → pause → уход указателя → ожидание 350 мс. Затем снимки всей сцены, её содержимого и SVG, ожидание 700 мс и вторые снимки тех же областей. Скрипт: `scripts/dialogue-native-pause-diagnose.mjs`.

В обеих последовательностях все три пары дают точное равенство PNG и декодированных пикселей: максимальная разность канала 0, изменённых пикселей 0. Атрибуты и вычисленные свойства SVG совпали; анимации в сцене также совпали. Лично просмотрен `default-scene-a.png`: ось и точка −4 читаются, плеер действительно показывает состояние паузы.

У сцены непрозрачный базовый фон `rgb(21, 17, 31)`. Глобальная `ui-haze-drift` продолжала работать вне сцены, но в данном прогоне не изменила ни одного пикселя внутри снимков. В `DialogueArt` положения, длины, opacity и подписи вычисляются из единого elapsed таймера, отдельных CSS-анимаций фигуры не обнаружено.

Обнаружено перемещение контейнера при захвате: до первого набора locator-снимков внутренний `studio-chat-scroll.scrollTop` был 2521, после — 2412; верх сцены сместился с 21.703125 до 130.703125. `locator.screenshot()` может сам прокручивать элемент/родителей, чтобы захватить его целиком. Во втором наборе положение уже было стабильным. Это объясняет необходимость фиксировать положение, а не считать разницу файлов самостоятельным доказательством движения учебной фигуры.

Первоначальный FAIL в `studio-live-native-0.5/report.json` остаётся FAIL: обе исходные PNG тогда не были записаны, поэтому точную причину того конкретного расхождения доказать нельзя. Настоящий replay сохранённой сцены этот дефект не воспроизвёл; оснований изменять clock или renderer по данному результату нет.

Для следующей живой проверки нужно сохранить обе PNG до assert, декодированные pixel metrics, geometry и координаты/scroll родителя. Перед измерением — завершить прокрутку, сделать предварительный захват либо дождаться стабильных координат после приведения элемента в видимую область. Не подменять проверку точного совпадения допуском без сохранённых метрик.

Все окна этого диагностического запуска закрыты. Продукт не изменён.
