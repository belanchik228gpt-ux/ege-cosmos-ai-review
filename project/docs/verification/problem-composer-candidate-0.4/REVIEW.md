# Проверка CSS-кандидата: нижняя граница панели диалога

Это **проверка временного CSS-кандидата**, а не финальная приёмка установленной сборки. Настоящий EXE с ASAR `3eeb5c9da69180f3296445b8134b4a89990fcc5ff4cf823e3dce856d689692d9` запущен с чистым тестовым профилем и пустым runtime. Правило `.tutor-workspace .tutor-conversation` прочитано из актуального `src/ui/tutor-workspace.css` и применено только к тестовой странице через Playwright `addStyleTag`. Точный CSS, его SHA-256, хеш исходного файла и координаты сохранены в `result.json`. Файлы продукта эта проверка не изменяла.

Проверены три состояния при 1280×720: первый вопрос о ряде клеток; раскрытое исходное условие; длинный вопрос о выборе действия с раскрытым условием и заполненным composer. Во всех трёх случаях header, условие, прокручиваемая история, textarea и кнопка отправки находятся внутри панели высотой 420 px. Для длинного вопроса: header 65 px, условие 123 px, история 64 px, composer 166 px. Нижняя граница отправки 825.39 px при нижней границе панели 844.39 px — около 19 px запаса.

Все четыре PNG открыты и просмотрены лично. Обрезка textarea/кнопки границей карточки устранена. В исходном положении страницы часть панели ниже видимого экрана, но обычная прокрутка вниз показывает её целиком; четвёртый снимок фиксирует именно видимую область 1280×720 после прокрутки. История диалога остаётся небольшой и требует внутренней прокрутки. Дополнительные масштаб/шрифт и более длинные нетиповые условия этим ограниченным прогоном не проверялись.

Результат: **3/3 проверок геометрии PASS**, четыре визуально просмотренных снимка, ошибок страницы нет, собственное окно закрыто, модель не запускалась. Следующий шаг — повтор основного native-скрипта после включения CSS в новый ASAR. Исходная сборка `3eeb…` без инъекции остаётся с ранее зафиксированным визуальным FAIL.
