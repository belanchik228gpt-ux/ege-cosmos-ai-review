# Диагностика времени ответа локальной модели

Испытание 8 сентября 2026 года на Ryzen 5 5600, 32 GB RAM и RTX 3070 Ti 8 GB. Исследовался таймаут первого вопроса из установленного EGE Cosmos. Сторонние приложения не закрывались и не перенастраивались.

## Причина сбоя

Запрос состоял из 2178 символов: 715 токенов до добавления шаблона разговора и 736 токенов в обработке сервером. При контексте 4096 токенов это не переполнение. Локальный сервер исправно обработал запрос и сформировал короткий ответ. Однако при высокой внешней загрузке видеокарты он затратил 53.8 секунды, поэтому штатный 45-секундный таймаут прервал ожидание.

Первоначальный сбой установленной EXE: запуск сервера 14 секунд, затем таймаут генерации 45 секунд. Прямое воспроизведение с тем же UI-контекстом и увеличенным только в диагностическом скрипте сроком позволило получить фактические серверные тайминги.

## Измерения

| Конфигурация | Запуск | Обработка запроса и ответ | Подробности |
| --- | ---: | ---: | --- |
| GPU, исходный batch | 30.3 с | 53.8 с | 736 токенов запроса: 19.56 с; 58 токенов ответа: 34.19 с, 1.67 токена/с. Наблюдалась 100% загрузка GPU и 434 MiB свободной VRAM во время работы. |
| CPU, установленный runtime | 8.97 с | 34.49 с | 56 токенов ответа; во время испытания GPU сторонних приложений оставалась загружена на 100%. |
| GPU, batch и microbatch 128 | 7.14 с | 13.58 с | Запрос: 8.86 с; 58 токенов ответа: 4.69 с, 12.15 токена/с. Вычислительный буфер CUDA 25.08 MiB. После испытания внешняя загрузка GPU составляла 26%. |

Это не контролируемый тест превосходства одной конфигурации: нагрузка сторонних приложений менялась. Нельзя приписывать всё ускорение уменьшению batch. CPU не выбран постоянным предпочтительным backend, поскольку GPU при доступных ресурсах заметно быстрее.

## Изменение приложения

Установлены явные `-b 128 -ub 128`, ограничивающие размер обработки одного блока и временную память. Контекст 4096, одна параллельная генерация, автоматическое распределение слоёв и резерв видеопамяти сохранены. Таймаут генерации 45 секунд не увеличен. GPU остаётся предпочтительным backend; если его запуск не удаётся, запускается CPU. Автопереключения CPU по одному показателю GPU-загрузки нет.

При перегрузке устройства языковая модель всё ещё может не уложиться в срок. В этом случае приложение должно возвращать понятное сообщение и оставлять доступными сцену, проверяемые задания и локальные подсказки. Эта ограниченность не скрывается сообщением об успешной генерации.

## Воспроизведение

`scripts/runtime-diagnose.mjs` принимает необязательный путь к изолированному профилю первым аргументом. Без аргумента используется самодостаточный тестовый контекст. `COSMOS_RUNTIME_DIR` выбирает установленный runtime, `COSMOS_DIAG_BACKEND=cpu` включает CPU только в диагностике, `COSMOS_DIAG_BATCH=128` задаёт тестовый размер блока.

Скрипт сохраняет локальные сырые логи только в исключённый из Git `runtime/qa/diagnose`. В этом документе приведены числовые результаты; ключи сервера и сырые диагностические журналы не публикуются. Производственный таймаут не зависит от увеличенного срока диагностического скрипта.
