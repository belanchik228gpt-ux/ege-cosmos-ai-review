## Обнаруженный дефект сохранения

В тестовом `learning-state.v1.json` после завершения два разных сообщения имеют ID `message-f6354683-6053-43f8-87fa-3f1523f4d80c`: первое `kind=summary` с итогом, второе `kind=model` с определением модуля. Новое содержимое реально пришло, но повторный ключ нарушает идентичность сообщений. Причина подтверждена чтением TutorRoom: pendingId берётся из предыдущего Cosmos-сообщения даже для finished, затем сообщение добавляется с этим же ID. Дефект передан root, этот агент продукт не менял.
