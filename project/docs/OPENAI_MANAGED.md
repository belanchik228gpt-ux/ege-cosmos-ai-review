# OpenAI в Cosmos 0.5: штатный вход и отдельная сессия

Cosmos использует официальный **Codex app-server 0.153.4**, поставляемый через `@openai/codex@0.153.4-win32-x64`. Это клиент штатного протокола OpenAI, а не собственная реализация OAuth и не извлечение авторизации установленного Codex. Лицензия runtime — Apache-2.0; `LICENSE` и `NOTICE` официального тега включены в `runtime/openai`. Код приложения имеет собственный лицензионный статус.

Протокол и его поля сверены с [официальной документацией app-server](https://learn.chatgpt.com/docs/app-server) и с TypeScript-схемой, сгенерированной самим поставляемым бинарником. Особенность фактической версии: значение approval policy `untrusted` отклоняется при запуске, хотя ещё встречается в схеме и документации. Используется поддерживаемое `on-request`, отключённые инструменты и `environments: []`.

## Вход, сохранение и ошибки сети

Кнопка входа вызывает `account/login/start` с типом `chatgpt`; затем Electron открывает только HTTPS-адрес точного официального origin `auth.openai.com` или `chatgpt.com`, возвращённый app-server. Завершение определяется уведомлением `account/login/completed` и подтверждается `account/read`, а не закрытием браузера. Повторное нажатие не создаёт параллельных попыток. Незавершённую попытку можно отменить; срок ожидания ограничен десятью минутами.

Дочерний runtime получает собственный `CODEX_HOME`: `EGE Cosmos Studio/openai-cosmos` внутри каталога данных Cosmos. Он также получает собственные HOME/USERPROFILE/APPDATA/TEMP. Переменные ключей API и авторизации текущего Codex не наследуются. Cosmos **не читает auth.json**, не копирует токены из пользовательского Codex и не выводит токены в UI или диагностике. Штатный runtime управляет файлом credentials в своём home и их обновлением, как описано в [документации авторизации](https://learn.chatgpt.com/docs/auth). Выбран режим `cli_auth_credentials_store = "file"`, чтобы исключить общий системный keyring.

`account/read` вызывается с `refreshToken: false`; доступность runtime, сохранённый вход и доступность сети отображаются раздельно. Ошибка проверки или ответа **не вызывает logout**. Разлогинивание производится только явным `logoutOpenAI`. При перезапуске процесса runtime снова использует тот же Cosmos home. Список моделей приходит через `model/list`; наличие модели в каталоге ещё не подтверждает доступность аккаунту, квоту или успешный ответ.

## Ответ преподавателя и границы инструментов

`generateOpenAITutor` получает `conversationId`, предмет, инструкции занятия и историю ровно одной комнаты. Для каждого запроса создаётся свежий ephemeral app-server thread. Сохранённую переписку ведёт Cosmos и передаёт её в следующем запросе; скрытого повторного добавления предыдущего сообщения при retry и смешивания комнат нет. Сохранение входа независимо от этих временных потоков. История ограничена 120 сообщениями и 120 000 символами; фотография — проверенные PNG/JPEG до 10 МБ и 20 мегапикселей, декодируется локально и уменьшается до 2048 пикселей. В модель передаётся `image` data URL, а не произвольный локальный путь.

Модель возвращает свободный учебный Markdown/LaTeX и необязательные данные сцены. `outputSchema` ограничивает envelope и типы: `text`, `title`, `question`, `phase`, `summary`, `scene`. Семь видов сцен содержат 2–8 шагов с подписями, формулами и конечными числами. Backend повторно валидирует ответ. Он не выполняет HTML, CSS, JavaScript, формулы или URLs из ответа. Текстовый ответ без JSON допускается без выдуманной сцены; повреждённый JSON не показывается ученику.

Поток `item/agentMessage/delta` теперь используется для временного показа верхнего поля `text` до завершения остального JSON. `desktop/openai-progress.cjs` разбирает ограниченный JSON-префикс, включая разорванные escape-последовательности и пары Unicode; вложенные поля, commentary, reasoning и протокол целиком не передаются. Повреждённый текущий префикс не даёт новых событий; если ошибка возникла после ранее корректного префикса, окончательная ошибка запроса требует удаления временной реплики в UI. Неполный текст не является подтверждённым или сохранённым ответом.

`onOpenAITutorProgress(listener)` возвращает отписку. Событие содержит `requestId`, `conversationId`, `state: 'writing'`, накопленный `text` и `elapsedMs`; не чаще 10 раз в секунду, до 16 000 символов текста из envelope до 32 000 символов. Необязательный `requestId` запроса задаёт UI; для старого клиента backend создаёт UUID. Проверяются активные thread/turn/item и поколение запроса, таймеры удаляются при отмене, завершении и ошибке. Сцена и постоянная история по-прежнему используют только полный результат `parseTutorOutput`. `firstVisibleTextMs`, когда есть, измеряет время до первой передачи временного текста через backend callback, а не до фактической отрисовки пикселей окна. Callback не пишет историю или документы.

Настройку модели и effort потоковый режим не меняет. Отдельная реальная проверка runtime 0.153.4 в пустом Cosmos home дала `config.model_reasoning_effort = null`, каталожный default GPT-6-Astra `low`, thread reasoningEffort `null`; это не измерение эффективного усилия ранее выполненного авторизованного ответа. Сводка без входа и генерации: `verification/openai-protocol-0.5/effort-check.json`. 41 целевой тест транспорта/сервиса/потокового парсера проверяет отмену, соседние запросы, повреждённые данные, throttle и финальную валидацию. Реальный авторизованный streaming проверен в packaged EXE с SHA-256 ASAR `08cd147c9983500c7eebb1aff4f8fafc1bd72bef393f49af9c7cced9aa20a859`; результаты и границы перечислены ниже. Проверка этой кандидатной EXE не заменяет приёмку окончательной установленной сборки.

Отключены shell/unified_exec, apps, plugins, browser/computer use, multi-agent, goals, hooks, image generation, просмотр файлов и поиск skills. Эффективные критические флаги и отсутствие MCP проверяются через `config/read`; неподтверждённая конфигурация останавливает запуск. На thread и turn передаётся `environments: []`, дополнительные tools/capability roots не предоставляются, sandbox read-only без сетевого доступа инструментов. Любой запрос разрешения команды/изменения файла отклоняется; прочие серверные запросы инструментов получают отказ. Такие события не исполняются Cosmos и прерывают учебный ответ. Это проверенные настройки runtime и транспортная граница; отдельный реальный adversarial model-run после авторизации ещё требуется.

Обычный RPC ограничен 15 секундами, генерация — общим бюджетом 100 секунд с учётом подготовки. Отмена посылает `turn/interrupt` только для собственного thread/turn, а при неответившем процессе завершает собственный child. На выходе приложение завершает свой app-server; это не выход из аккаунта. В diagnostics записываются только тип результата, длительность и хеш идентификатора комнаты, без сырых RPC, stderr, URL входа, фотографии или переписки.

Структурированный формат не доказывает математическую/историческую истинность ответа. Эта облачная ветка не выдаёт дополнительную локальную Qwen-проверку или простое совпадение цитаты за проверку OpenAI по интернету. Источники, задания, самостоятельные попытки и подтверждение освоения остаются отдельными учебными данными.

## Фактически проверено

`node scripts/openai-readonly-check.mjs` запускает настоящий поставляемый бинарник с новым пустым профилем, без браузера и авторизации. Проверены initialize, эффективные ограничения, account/read (signed-out), model/list, создание/отписка ephemeral thread, честный отказ генерации до входа. Результат: `docs/verification/openai-protocol-0.5/read-only.json`.

В отдельном свежем профиле также действительно выполнены `account/login/start` → получение адреса `https://auth.openai.com` → `account/login/cancel`. В этой ранней проверке браузер не открывался, авторизация не выполнялась; после отмены `account/read` вернул signed-out. Сохранены только origin и состояния, без полного OAuth URL: `docs/verification/openai-protocol-0.5/login-start-cancel.json`. Позднее ученик выполнил настоящий вход Cosmos; последующие native-проверки использовали эту Cosmos-сессию через явный auth-home override, с изолированными учебными данными, без чтения или копирования credentials.

[Авторизованная проверка четырёх предметов и фото](verification/studio-live-native-0.5-continuation/report.json) завершилась PASS по шести группам на ASAR `0285dddca93a3c5c937605dabe579d792ce06d80f3ff4c9cd7e6ea0fb98cb37a`, модель `gpt-6-astra`. Подтверждены сохранённый вход, последовательные ответы, фактический рисунок с паузой/переходами, чтение прикреплённого печатного QA-изображения прямоугольника 7 × 4, отдельные разговоры русского языка, истории и обществознания, перезапуск и следующий настоящий ответ. Изображение было авторским контрольным примером; ручная расшифровка не подставлялась. Первоначальный [прогон](verification/studio-live-native-0.5/report.json) сохраняет FAIL проверки стабильности остановленных пикселей после трёх реальных ответов; успешный отчёт продолжения хранится отдельно и не изменяет этот исходный результат.

[Streaming, отмена, экспорт и продолжение после рестарта](verification/studio-stream-native-0.5/report.json) — PASS четырёх групп на ASAR `08cd147c9983500c7eebb1aff4f8fafc1bd72bef393f49af9c7cced9aa20a859`, модель `gpt-6-astra`, запуск 08.09.2026 в 22:32–22:36 по Москве. В четырёх завершённых запросах первое событие текста пришло через **12,305–12,488 секунды**, полный результат — через **39,948–51,090 секунды**. Это фактические измерения данного прогона, а не обещание скорости. Скриншот подтверждает временный текст до завершения; проверка диска подтверждает отсутствие сохранения частичной реплики. Реальная отмена очистила поток, повторный запрос дал ответ; после перезапуска восстановились вход и переписка и пришёл ещё один настоящий ответ. Через фактический desktop bridge из сохранённого разговора созданы [HTML](verification/studio-stream-native-0.5/actual-chat-note.html) и [PDF](verification/studio-stream-native-0.5/actual-chat-note.pdf) размером 76 895 байт с локальными шрифтами формул. Это реальные файлы packaged EXE, не синтетический ответ.

В открытой комнате последняя фотография остаётся во временном кеше и может повторно передаваться OpenAI с уточнением. Данные фотографии не записываются в учебную историю: после ухода из комнаты с выгрузкой компонента или перезапуска для повторного просмотра оригинала нужно прикрепить её снова. Сохранённое имя файла и прошлый текст условия не означают, что модель снова видит фото. В раннем реальном ответе после рестарта модель прямо сообщила, что опирается на сохранённую переписку, а не на исходное изображение.

**Финальная установленная 0.5 проверена отдельно.** `verification/studio-installed-live-0.5/report.json`: настоящий EXE из `test-results/installed-app`, ASAR `d75fb7d4e00fae1ec67e8c4bb5261ed6da91f5f3b481b890ecfbcf744ca67cfe`, три группы PASS. Два реальных ответа GPT-6-Astra: продолжение с сохранёнными данными рисунков и итог занятия. Первые части текста через 12,325 и 13,099 с, завершение через 47,835 и 47,659 с. Преподаватель не выдал ответ на новый пример, не объявил просмотр рисунка подтверждённым и не засчитал самостоятельное применение по одному разобранному примеру. Официальная ссылка ФИПИ присутствует в тексте ответа. Из установленного приложения созданы HTML/PDF; после перезапуска восстановлены вход и разговор. Учебные данные тестовые, вход предоставлен пользователем штатно; токены не читались и не копировались. Ранее указанные хеши остаются свидетельствами соответствующих кандидатов. Отдельно не проверены многодневное истечение/обновление токена, все типы сетевых сбоев и универсальная предметная безошибочность.

Транспортные тесты используют явно синтетический RPC fixture: порядок ответов, дробление строк, отказ инструментам, ограничение времени, отмена, очистка busy, отсутствие logout на probe failure, изоляция двух последовательных предметных запросов, валидация сцен. Они **не заменяют** перечисленные реальные запуски и не доказывают token refresh, многодневную устойчивость или приёмку другой сборки.

Скрипт поставки `scripts/download-openai-runtime.mjs` использует фиксированную версию npm, сверяет SHA-512 integrity архива, проверяет имена архивных путей и сохраняет SHA-256 каждого файла в manifest. Runtime не хранится в Git; packager должен включать весь `runtime/openai` как extraResources. Обновление версии требует повторного чтения protocol schema, проверки конфигурации и сценариев авторизации.

## Проверка файлов установленного релиза 0.5

После фактической сборки, подготовки комплекта и установки `node scripts/verify-release.mjs` сравнивает EXE/ASAR установленного приложения с portable-сборкой и читает `package.json` внутри обоих ASAR. Версия должна совпадать с версией релиза: одинаковые старые ASAR не подтверждают новую поставку. Для `runtime/openai` сравнивается полный список файлов и SHA-256/размер каждого файла между исходным runtime, portable и установленной копией. Затем исходные файлы отдельно сверяются с `manifest.json`; проверяются фиксированные package/version/source/integrity, обязательные `LICENSE`, `NOTICE`, `codex.exe` и платформа Windows x64. Лицензии входят в отчёт со своими контрольными суммами. Сам архив npm этим скриптом повторно не скачивается и не хешируется; его SHA-512 остаётся метаданными проверки загрузки.

Успешный запуск записывает `docs/verification/release-verification-0.5.json` и текущий `release-verification.json` с точной версией, SHA-256 ASAR и временем проверки. Старые отчёты UI/моделей не читаются и не переносятся: поля native UI, managed auth, live OpenAI и локальных моделей явно отмечены `not-run-by-this-verifier`. Целостность файлов не доказывает успешный вход или ответ модели. Обновление самого скрипта также не является проверкой ещё не установленной сборки.

Логика верификатора проверена отдельно командой `node scripts/verify-release-check.mjs`: 11 проверок на маленьких, явно синтетических файлах, без запуска EXE, установщика, OpenAI или GPU. Проверены полный комплект, отклонение старой версии ASAR, повреждённого OpenAI exe, одинаково изменённой лицензии во всех копиях при прежнем manifest, изменённого manifest, дубликатов и выхода пути за каталог, отсутствующего NOTICE, повреждённой vision DLL, изменённого PDF manifest и старого установщика. Эти fixture-результаты находятся только в изолированном `test-results` и не являются результатами приёмки релиза.

Памятка, создаваемая `scripts/offline-kit.mjs`, различает офлайн-установку и работу основного преподавателя: для OpenAI нужны штатный вход и интернет; локальные занятия, документы и дополнительная Qwen доступны без аккаунта. Фото, прикреплённое к разговору OpenAI, отправляется OpenAI; локальное распознавание остаётся отдельным режимом.
