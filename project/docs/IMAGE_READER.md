# Локальное чтение фотографий учебных заданий

В версии 0.3 используется отдельная настоящая vision-модель **Qwen3-VL-4B-Instruct**, запускаемая приложением через имеющийся llama.cpp b10850. Изображение передаётся в мультимодальную часть `/v1/chat/completions`; текстовый Qwen3-8B изображений не получает и не объявляется способным их видеть. Аккаунт, облачный API и отдельное приложение для чтения фото не нужны.

Модель выбрана из официального GGUF-репозитория Qwen. Поддержка image content и отдельного `--mmproj` описана в [документации llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/docs/multimodal.md), веса и способы локального запуска — в [официальной карточке Qwen3-VL-4B-Instruct-GGUF](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct-GGUF). Проверено 8 сентября 2026 года. Windows.Media.Ocr не используется: [документация Microsoft](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr?view=winrt-26100) указывает требование package identity для настольных приложений; текущая поставка NSIS не является пакетом MSIX.

## Что получает ученик

Результат — распознанный текст условия, доступный для исправления перед отправкой преподавателю. Модель получает инструкцию переписывать надписи буквально, сохранять числа, знаки, дроби, модуль и единицы, не решать задачу и отмечать неразборчивые места. Текст с фото трактуется как данные, а не команды для программы.

Любой успешный результат имеет `uncertain: true` и напоминание проверить условие. Численного показателя «уверенность 99%» нет. Даже корректно распознанное условие не является проверенным решением. Задачи поддерживаемых типов проверяет отдельный вычислительный модуль; объяснение текстовой модели по-прежнему проходит обязательную сверку по переданным учебным фрагментам. Авторское проверенное решение помечается `cosmos-training`, а не официальным заданием ФИПИ.

Ошибки чтения или отсутствие моделей не заменяются выдуманным распознанным текстом. Можно повторить чтение, обрезать фото или ввести условие вручную. При превышении длины ответа показывается предупреждение, что условие может быть неполным.

## Нативная граница и ресурсы

`desktop/image-reader.cjs` принимает только канонические `data:image/png;base64,...` и `data:image/jpeg;base64,...`: до 10 MiB исходных байтов, 20 миллионов пикселей и не более 16000 пикселей по стороне. Сигнатура, размеры PNG/JPEG и границы JPEG-сегментов проверяются в main process до декодирования. SVG, URL, пути к файлам и несоответствующие сигнатуры отклоняются. Затем встроенный `nativeImage` декодирует настоящие байты; для модели длинная сторона уменьшается до 2048 пикселей. Изображение продуктом не записывается на диск и не попадает в диагностический журнал. Оно передаётся только своей локальной службе на `127.0.0.1`, без отправки внешнему серверу.

Vision и текст используют выбранный режим Авто / Видеокарта / Процессор. Авто пробует CPU только после неудачного запуска GPU. Слои GPU подбираются llama.cpp, контекст — 4096, batch/ubatch — 128, image tokens — 1024–1536. CPU-проектор запускается с `--no-mmproj-offload`.

Одновременно приложение держит только один из этих двух своих workers: перед фото останавливает свободный текстовый процесс; после фото завершает vision-процесс; следующий текстовый вопрос снова запускает Qwen3-8B. Занятый ответ не прерывается ради фото. Учебные сцены и редактирование текста продолжают работать. Приложение не завершает сторонние процессы пользователя.

Чтение ограничено общим сроком 150 секунд. Запуск GPU — 35 секунд, CPU — 55 секунд; действуют те же пределы, что у текстового runtime. Кнопка отмены прерывает реальный запрос и только свой дочерний процесс. Очередь освобождается после его завершения, включая случай уже вызванной отмены. Если завершение неожиданно занимает больше трёх секунд, интерфейс возвращает ограниченный по времени результат, а отдельный обработчик выхода удерживает резервирование GPU до фактического завершения процесса. Внутренние ошибки доступны только в диагностике.

readProblemImage({ dataUrl, subject? }): Promise<{
  ok: boolean;

  model?: string;
  detail: string;

IPC разрешён только главному доверенному окну приложения. Проверка статуса не запускает модель. Наличие файлов сообщает доступность пакета, но не обещает, что любой драйвер или снимок успешно пройдёт обработку.

## Файлы поставки и воспроизводимость

Официальный репозиторий: `Qwen/Qwen3-VL-4B-Instruct-GGUF`. Неизменяемая ревизия: `1cd86afb9a95c410a6038ab3b40d8b578c892266`. Лицензия Apache-2.0 указана в [карточке исходной модели](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct).

| Файл                                |       Байт | SHA-256                                                            |
| ----------------------------------- | ---------: | ------------------------------------------------------------------ |
| Qwen3VL-4B-Instruct-Q4_K_M.gguf     | 2497281664 | `66358cb18bb6b3b1b6675aa412c7a88ef01d228f481184d13668e5201c730a0a` |
| mmproj-Qwen3VL-4B-Instruct-F16.gguf |  836180256 | `256f3a43bd4205ffef48d6b92715e1e70b5b0e9aef06522584967513a9985331` |

Это примерно 3.33 GB дополнительных весов. Вместе с текстовой моделью — примерно 8.36 GB, без учёта приложения, DLL и официальных PDF. Размер загрузки не равен потреблению VRAM.

```text
runtime/
  models/Qwen3-8B-Q4_K_M.gguf
  models/vision/Qwen3VL-4B-Instruct-Q4_K_M.gguf
  models/vision/mmproj-Qwen3VL-4B-Instruct-F16.gguf
  vision-artifacts.json
  licenses/Qwen3-VL-LICENSE.txt
  licenses/Qwen3-VL-MODEL-CARD.md
```

`node scripts/vision-download.mjs` скачивает фиксированные официальные файлы, проверяет итоговые размер и SHA-256 и сохраняет манифест. Незавершённые диапазоны не получают конечное имя модели. Для загрузки используется Python standard library с HTTPS Range; `COSMOS_PYTHON` позволяет задать путь Python. `node scripts/vision-download.mjs --check` проверяет уже скачанные файлы полностью офлайн и не запускает модель. Веса исключены из Git.

`offline-kit.mjs` проверяет оба vision-хэша, создаёт `Cosmos-Models/vision` рядом с установщиком и добавляет модели в portable. Установщик копирует все три GGUF; при ошибке копирования сообщает ошибку и возвращает ненулевой код. Текстовая модель и projector входят в комплект как отдельные файлы, чтобы не упираться в размер одного NSIS-архива. `verify-release.mjs` сравнивает установленный manifest, размеры и SHA обоих vision-файлов с проверенной поставкой; расширенная проверка также сверяет все runtime DLL и лицензии, PDF-манифест и installer в offline-kit. Первичная установка 0.3 с моделями выполнена, но сама правка проверочного скрипта не является успешным прогоном на последней сборке; окончательные результаты находятся в отчёте выпуска.

## Фактическая проверка 8 сентября 2026

`scripts/vision-fixtures.py` создал три **авторских печатных контрольных изображения**, а не фотографии ученика. `scripts/vision-runtime-check.cjs --sequence` запустил настоящий Electron `nativeImage`, настоящий llama.cpp и настоящие GGUF. BrowserWindow не открывался; это проверка нативного backend, не визуальная приёмка установленного EXE.

Последний прогон после исправления ожидания завершения процесса: 17:01 по Москве. [JSON с настоящими ответами и таймингами](verification/vision-runtime/result.json).

| Шаг                     | Наблюдение                                                                 | Время с запуском |
| ----------------------- | -------------------------------------------------------------------------- | ---------------: |
| Текст до чтения фото    | Настоящий Qwen3-8B; объяснение первого шага + обязательная цитатная сверка |           4.71 с |
| Прямоугольник           | Точное сохранение `Длина 7 см, ширина 4 см`                                |           4.87 с |
| Дроби и модуль          | Точное сохранение `3/8 + 1/4` и `\|x - 2\| = 5`                            |           4.82 с |
| Русский язык            | Предложение переписано без самовольного исправления запятой                |           4.20 с |
| Текст после чтения фото | Повторный настоящий ответ Qwen3-8B с цитатной сверкой                      |           4.98 с |

Все три распознанные строки сравниваются со сформированным заранее текстом; допускается только нормализация NFC и пробелов. На этом прогоне 3/3 совпали. После каждого чтения проверены освобождение резерва и завершение vision-worker. После всего прогона собственных llama-server процессов не осталось.

В первом прогоне холодный старт Qwen3-8B занимал около 20 секунд, весь первый текстовый запрос — 22.7 секунды. Поэтому более быстрый повтор не является обещанием постоянной скорости. Два текстовых ответа объяснили один первый шаг; этот тест подтверждает продолжение диалога и транспорт, **не полное решение задач и не всю педагогическую приемлемость**.

33 целевых unit-теста прошли: 14 проверок границы изображений/отмены/очереди, 7 выбора backend и 12 обязательной сверки. Они не подменяют фактическое распознавание. TypeScript проверен отдельно. Качество почерка, тёмных или наклонных фото, сложных геометрических чертежей, нескольких колонок и формул вне этих контрольных строк пока не измерено. Процессорный режим vision и фактический photo UI окончательной установленной версии требуют отдельной проверки.
