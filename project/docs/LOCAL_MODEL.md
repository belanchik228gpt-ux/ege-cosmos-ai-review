# Локальный преподаватель Cosmos

Преподаватель работает в основном окне EGE Cosmos, без аккаунта ChatGPT. Учебные сцены, проверяемые задания, память и экспорт доступны и при отсутствии модели. Ответ языковой модели обозначается отдельно от подготовленного локального материала.

## Пакет для первого испытания

- Модель: **Qwen3-8B Q4_K_M**, официальная GGUF-квантизация Qwen, 8.2B параметров.
- Размер весов: 5 027 783 488 байт (примерно 4.68 GiB).
- Лицензия модели: Apache 2.0. Модель не обучалась заново и не выдаётся за разработанную с нуля большую языковую модель.
- Движок: **llama.cpp b10850**, лицензия MIT.
- GPU: официальный Windows x64 CUDA 12.4 пакет; CPU: отдельный официальный Windows x64 пакет.
- Проверенный компьютер разработки: Ryzen 5 5600, 32 GB RAM, RTX 3070 Ti **8192 MiB VRAM**, драйвер NVIDIA 610.88.
- Контекст: 4096 токенов; одна генерация одновременно; thinking выключен; ответы ограничены по длине.
- Логический и физический batch: 128 токенов каждый. Это ограничивает временную память обработки запроса и уменьшает размер отдельных вычислений.

Версия выбрана как воспроизводимая исходная точка для учебных проверок. Это не заявление о превосходстве над всеми более новыми моделями. Нужны отдельные предметные оценки качества.

## Воспроизводимая установка пакета

Из корня проекта:

```powershell
node scripts/runtime-download.mjs
Expand-Archive -LiteralPath '.\runtime\downloads\llama-cuda.zip' -DestinationPath '.\runtime\llama' -Force
Expand-Archive -LiteralPath '.\runtime\downloads\cudart.zip' -DestinationPath '.\runtime\llama' -Force
Expand-Archive -LiteralPath '.\runtime\downloads\llama-cpu.zip' -DestinationPath '.\runtime\llama-cpu' -Force
```

Скрипт использует зафиксированные версии upstream. SHA256 каждого архива и GGUF проверяется до присвоения конечного имени. Незавершённые `.part` не запускаются. Для крупных файлов используются проверяемые HTTP Range-запросы и итоговая проверка SHA256 всего файла. Лицензии сохраняются в `runtime/licenses`.

Структура для разработчика и сборщика:

```text
runtime/
  llama/llama-server.exe       # CUDA и соседние DLL
  llama-cpu/llama-server.exe   # CPU и соседние DLL
  models/Qwen3-8B-Q4_K_M.gguf
  licenses/
  artifacts.json
```

`runtime` исключён из Git. В дистрибутив входят только проверенные модель, необходимые EXE/DLL, лицензии и манифест — без `downloads`, временных фрагментов и QA. Большой полный офлайн-пакет распространяется отдельно от исходников.

## Работа процесса

Модель запускается приложением при первом вопросе, в скрытом дочернем процессе. Сервер слушает только `127.0.0.1` на свободном порту и требует случайный ключ для этой сессии. Внешний сервер, аккаунт или облачный API не используются. Интерфейс не имеет доступа к произвольным IPC, файлам и командам.

Количество слоёв GPU подбирается llama.cpp под свободную видеопамять с запасом 768 MiB. В режиме Авто после неудачного запуска GPU приложение пробует CPU; явные режимы используют только выбранный runtime. Другие приложения, в том числе Unreal, могут уменьшать свободную видеопамять и снижать скорость. Приложение не завершает сторонние процессы.

Испытание 8 сентября выявило влияние конкурентной GPU-нагрузки: тот же короткий запрос требовал 53.8 секунды при 100% загрузке GPU сторонними приложениями и превысил штатный срок 45 секунд. Прямой диагностический запрос с увеличенным только в тесте сроком завершился нормально — переполнения контекста и зависания IPC не было. CPU ответил за 34.5 секунды. После ограничения batch до 128 GPU ответил за 13.6 секунды, но внешняя нагрузка к тому времени уменьшилась; весь выигрыш нельзя приписывать изменению batch. Производственный таймаут не увеличен. Автоматического переключения на CPU только по проценту GPU-загрузки нет. Подробные фактические измерения приведены в `docs/verification/RUNTIME_PERFORMANCE.md`.

Запуск GPU ограничен 35 секундами, CPU — 55 секундами, одна генерация — 45 секундами. Отдельная сверка ответа ограничена 20 секундами, общий запрос вместе со стартом и сверкой — 160 секундами. При таймауте останавливается только собственный процесс модели; поле текста остаётся доступным, следующий вопрос может запустить процесс снова. Отклонение ответа из-за неподтверждённых сведений или неверного внутреннего JSON не останавливает здоровый процесс. Подробности попадают только в «Настройки → Диагностика». Закрытие приложения останавливает дочерний процесс.

Каждый запрос получает предмет, тему, сообщение, явно переданный контекст текущего занятия и обязательные учебные фрагменты `evidence`. Сервер не является хранилищем учебной памяти. Учебные факты хранятся отдельным атомарно записываемым файлом с резервной копией. Новое приложение использует отдельный каталог `%APPDATA%/EGE Cosmos Studio`, без чтения данных старого Cosmos.

## Обязательная сверка ответа с учебными фрагментами

В `ask` нет выключателя проверки. До запуска модельного процесса проверяется массив `evidence`: от 1 до 8 фрагментов, до 5000 символов текста суммарно, известный вызывающему учебному каталогу идентификатор и от 1 до 12 идентификаторов источников на фрагмент. Нативная граница проверяет структуру, длины и формат идентификаторов; выбор подлинных фрагментов локального каталога выполняет учебный слой. Отсутствующие или недопустимые фрагменты отклоняются до генерации.

Первый ответ остаётся внутренним кандидатом. Второй запрос той же модели получает новый список сообщений без истории диалога: доверенную инструкцию проверки и JSON с вопросом ученика, кандидатом и фрагментами. Эти поля трактуются как данные; инструменты, команды и поиск из содержимого не исполняются. Для воспроизводимости установлены `temperature: 0`, фиксированный seed и ограниченный JSON-формат. Детерминированные параметры не гарантируют битовую идентичность результатов на разных устройствах.

Результат допускается только при строгом `supported === true` и хотя бы одной непустой цитате длиной от 12 символов из существующего фрагмента. Проверяются все возвращённые цитаты: после Unicode NFC и нормализации пробелов каждая должна быть точной непрерывной подстрокой соответствующего текста. Список идентификаторов и сами проверенные цитаты возвращаются как `verification.evidenceIds` и `verification.evidence` с методом `local-model-review`. Причина проверки остаётся в техническом журнале.

Неподтверждённый, некорректный или просроченный результат возвращает `ok: false` со статусом `unsupported` либо `unavailable`. Исходный ответ кандидата не включается в возвращаемый объект и не выдаётся за проверенный ответ. Ответ HTTP ограничен 32 КБ до JSON-разбора, содержимое отчёта сверки — 8000 символами; причины и цитаты также ограничены.

Это дополнительная **модельная сверка той же моделью, а не независимое доказательство истины**. Совпадение цитаты подтверждает её происхождение, но само по себе не доказывает, что она обосновывает каждое утверждение ответа. Проверяющая модель может повторить ошибку первой. Механизм не выполняет живой поиск в интернете и не открывает целые учебники: он сверяет переданные фрагменты локальной базы. Доступность свежих интернет-материалов и корректность их отбора требуют отдельного механизма. Весь локальный учебный сценарий остаётся доступным при отказе сверки.

Учебный слой подбирает относящиеся к вопросу авторские объяснения и, для части тем, короткие заранее проверенные выдержки из опубликованных источников. Это небольшой локальный кэш цитат, а не загруженные целиком учебники и не новый интернет-запрос при каждом ответе; происхождение выдержек описано в `SOURCE_EXCERPTS.md`. Если поиск не находит подходящего совпадения, текущая тема комнаты не подставляется автоматически. Лексическое совпадение само по себе не гарантирует смысловую релевантность. В принятой реплике сохраняются точные цитаты, идентификаторы их источников и время сверки; ученик может раскрыть этот блок в диалоге.

Перед доставкой учебный слой дополнительно отклоняет известные предметные противоречия, URL, отсутствующие в опорном тексте четырёхзначные исторические годы и неверные числовые равенства в поддерживаемой простой арифметике. Это ограниченные программные проверки. Они не охватывают все даты, естественно-языковые рассуждения, алгебру, размерности и перевод единиц; пропущенное выражение не считается математически доказанным. Непрошедшая реплика не сохраняется как ответ модели: приложение показывает явно обозначенный локальный учебный материал.

Контракт и таймауты проверяются `tests/evidence-review.test.ts` через контролируемые ответы без запуска нейросети. Эти тесты подтверждают границы допуска, отсутствие утечки отклонённого кандидата и освобождение состояния busy, но не качество фактической проверки моделью. Новая двухэтапная проверка требует отдельного реального model smoke после сборки. Исторические прямые скрипты `runtime-smoke.mjs`, `runtime-pedagogy.mjs` и `runtime-diagnose.mjs` не передают новый обязательный `evidence` и теперь завершаются отказом; старые результаты этих скриптов не подтверждают новую проверку. Диагностическое увеличение таймаута из старого performance-скрипта нельзя применять к обязательной сверке.

Переменные `COSMOS_USER_DATA`, `COSMOS_DOCUMENTS_DIR`, `COSMOS_RUNTIME_DIR` позволяют запускать изолированные испытания. Они не настраиваются из сообщений ученика.

### Фактическая проверка двухэтапного запроса, 8 сентября 2026

`verification/evidence-runtime-check.json` фиксирует два последовательных запроса настоящему локальному Qwen3/llama.cpp с явно заданными тестовыми фрагментами. Оба прошли генерацию, отдельную сверку и проверку точной цитаты; второй запрос отправился после первого без перезапуска. Запуск GPU занял 19,006 секунды. Математический запрос занял 21,569 секунды вместе со стартом: генерация — 1,102 секунды, сверка — 1,443 секунды. Запрос по истории на прогретом процессе занял 1,596 секунды: генерация — 0,696 секунды, сверка — 0,900 секунды. Эти единичные измерения не прогнозируют скорость при иной нагрузке.

Математическое объяснение квадратного сантиметра соответствовало переданному материалу. Исторический ответ не назвал год целиком и верно указал конец X века, но затем задал вопрос о только что названном веке — педагогически слабый повтор. Этот дефект не был обнаружен проверкой фактов: точная цитата подтверждала век. После данного прогона инструкция преподавателя была дополнена запретом повторять вопросом уже сообщённый факт; этот JSON не подтверждает поведение обновлённой инструкции.

Результат подтверждает работу двух последовательных реальных запросов и второго прохода проверки. Это **не проверка packaged UI**, не полная предметная приёмка и не доказательство независимой истинности ответов. Конечная установленная сборка и качество обновлённого диалога проверяются отдельно.

## Ограничения первого выпуска

### Выбор устройства для модели

В «Настройки → Преподаватель» доступны «Авто», «Видеокарта» и «Процессор». Авто пробует запуск CUDA и переходит к CPU только при неудачном запуске; медленная генерация сама по себе не переключает устройство. Явный режим использует только выбранный runtime. В режиме процессора задаётся `-ngl 0`; параметры GPU и таймауты не увеличиваются ради успешного ответа.

Выбор сохраняется как `backend: auto | gpu | cpu` в том же `model.json`, что и явно выбранный путь модели. Для стандартного пакета сохраняется только режим, без привязки к абсолютному пути установки. Замена файла модели сохраняет режим. Обновление настроек запрещено во время запуска, ответа или другой операции настройки; между запросами останавливается только дочерний процесс этой копии Cosmos. Следующий вопрос запускает выбранную конфигурацию.

Экран показывает фактически запущенный режим и длительность последнего запроса с учётом запуска и сверки. Время сбрасывается при смене модели или режима и не является прогнозом скорости. Скорость CPU/GPU при разной внешней нагрузке не объявляется сопоставимой. Семь тестов `tests/model-backend.test.ts` проверяют режимы, сохранение конфигурации, запрет конкурентных изменений и остановку собственного процесса через заглушку launcher; эти тесты не запускают нейросеть и не подтверждают её качество или скорость.

`recordTutorCheck(reason)` сохраняет короткую техническую причину отклонения ответа только в диагностике (`tutor-check`, максимум 400 символов); он не добавляет неправильный ответ или техническое сообщение в учебную память.

Модель может ошибаться в фактах и решениях. Учебные результаты фиксируются проверяемым учебным модулем, а не утверждениями модели. Нет обучения весов на разговорах ученика. Нет подключения к ChatGPT. Распознавание речи отдельным офлайн-движком не входит в этот пакет модели. Автоматическое обновление материалов ФИПИ не происходит без отдельной проверки источников.

DOCX создаётся как настоящий OOXML-файл с UTF-8, A4 и редактируемым текстом. PDF создаётся встроенным Chromium через `printToPDF`. Только непустой сохранённый файл с проверенным размером возвращает успешный результат экспорта.

## Фото в версии 0.3

Добавлен отдельный Qwen3-VL-4B-Instruct с projector для настоящего локального чтения PNG/JPEG. Qwen3-8B остаётся текстовым преподавателем. Модели последовательно занимают память; отмена прекращает реальный запрос и ожидает завершения своего процесса. Для текстовых запросов обязательная цитатная сверка сохранена, в том числе при передаче проверенных авторских решений произвольных задач. Условия с фото всегда предлагаются ученику для исправления. Полный контракт, происхождение весов, реальные результаты печатных контрольных изображений и ограничения описаны в [IMAGE_READER.md](IMAGE_READER.md). Этот backend-прогон не заменяет приёмку фото в окончательно установленном приложении.

Инструкция больше не требует обязательного вопроса в конце каждой реплики: на прямое «почему» преподаватель объясняет конкретную причину. Проверяемый следующий вопрос задаёт учебный движок, связанный с активным условием и полем ответа. Фрагмент active-task/verified имеет приоритет над другим примером общей темы. Реальный контроль трёх реплик, найденные отказы и последний успешный повтор описаны в [tutor-runtime/REVIEW.md](verification/tutor-runtime/REVIEW.md); ограничения самопроверки не сняты.
