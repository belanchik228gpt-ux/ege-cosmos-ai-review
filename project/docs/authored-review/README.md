# Повторная приёмка 13 авторских сцен

Подготовлен новый сценарий `scripts/authored-scenes-review.mjs` для обновлённой навигации приложения. Прежние QA-скрипты не изменялись. 8 сентября 2026 года выполнены синтаксическая проверка и подготовительный запуск `COSMOS_DRY_RUN=1`: все 13 сцен сопоставлены с действительными уроками и шагом, содержащим формулу или вывод. Этот запуск не открывал приложение и не считается визуальным PASS.

Текущий результат после исправления часов: **13/13 PASS в установленном Windows EXE** с SHA-256 `app.asar` `aacc72fee1736e3de872d274dc183a59218fe28d9bfc07dd2a5e63fe5db17366`. Старый нативный FAIL сохранён ниже, он не переименован в успешный результат.

Сценарий открывает каждый урок через Ctrl+K и его точное название. Затем проверяет автоматический переход с фактическим изменением рисунка, побайтовое совпадение SVG на паузе через 650 мс, возвращение в тот же шаг и неподвижный кадр после ухода в меню, «Далее»/«Назад», формулу и повтор после конечного шага. Сохраняет отдельный кадр с формулой для каждой сцены, начальные и остановленные изображения, полный экран урока прямоугольника и результат JSON. Модуль числа проверяется отдельным сценарием `curriculum-visual-review.mjs`.

Режим по умолчанию — headless Chrome с исходным приложением Vite на 5173, результаты в `docs/authored-review/browser`. Для установленной сборки задаются `COSMOS_EXE` и `COSMOS_EXPECTED_ASAR`; результаты сохраняются отдельно в `docs/authored-review/native`, с путём EXE, хешем `app.asar` и исходных registry/clock. Используется отдельный профиль, без переопределения пути модельного runtime. Окно закрывается в `finally`.

Нативные изображения формулы для каждой сцены просмотрены лично; наличие файлов и автоматический PASS не использовались как замена просмотру.

## Диагностика установленной сборки 3e026…

8 сентября установленная сборка `3e026aa11d885e1a2d820fc0bf0e0cbfc181223e4a11739d3855126ec646bd89` реально запущена. Полная приёмка **не прошла** и остановлена на первом уроке, «Площадь прямоугольника».

В первой попытке два изображения на паузе отличались у 1440 из 205318 пикселей максимум на один уровень RGB; личный просмотр не выявил изменения геометрии. Для нативной диагностики добавлены отдельные показатели точного совпадения файлов, декодированных пикселей, максимальной разницы и доли изменившихся пикселей. Допуск не более одного уровня из 255 применяется только при одновременном точном равенстве SVG-геометрии и часов CSS-анимаций. Такой результат не называется побайтовым совпадением. Через обычные настройки в тестовом профиле отключено декоративное движение и свечение, учебная анимация оставлена включённой.

Повторная диагностика: на паузе совпали и файлы, и все пиксели (Δ0), геометрия и часы. После перехода «Сегодня» → Ctrl+K → тот же урок сохранился шаг 2, но частично построенный контур заменился полным. Изменились 32612 из 205318 пикселей (15,88%), максимальная разница канала 216. Перед уходом три CSS transition находились на паузе в момент 226,6 мс; после возвращения список анимаций пуст. Значения opacity и stroke-dashoffset сменились на конечные.

Лично просмотрены [кадр до ухода](native-rectangle-diagnostic/rectangle-paused-b.png) и [кадр после возврата](native-rectangle-diagnostic/rectangle-restored-a.png). Подробности — [JSON диагностики](native-rectangle-diagnostic/results.json). Это дефект восстановления промежуточного состояния анимации, переданный владельцу `useSceneClock.ts` для исправления. Сценарий не ослаблен до проверки одного лишь номера шага. Окно закрыто; остальные авторские сцены и новая нативная серия каталога на этой попытке ещё не проверены.

## Исправление и браузерное подтверждение

`useSceneClock.ts` теперь сохраняет вместе с курсором ограниченный снимок активных CSS-переходов: исходные keyframes, timing, путь элемента внутри сцены и время. При новом монтировании переход восстанавливается через Web Animations API на паузе с той же отметкой времени. Восстановленные эффекты удаляются после завершения и ручного перехода; они не перекрывают последующие шаги. Отдельно сохраняется режим ручного кадра, чтобы при возврате не пропадала уже открытая формула. Данные находятся только в sessionStorage состояния интерфейса, не в учебных фактах.

`motionSnapshot.ts` ограничивает размер, число переходов, допустимые свойства и длительность; неверные снимки пропускаются. Новые четыре проверки этого формата и существующие проверки сцен: **37/37 PASS**.

Сначала выполнен целевой проход прямоугольника и медианы, включая движение точки M на шаге 6. Пары кадров до/после возвращения лично просмотрены: [движущаяся M до ухода](browser-restoration-v2/median-moving-m-before.png), [после возврата](browser-restoration-v2/median-moving-m-restored.png). Пиксели совпали точно (Δ0).

Затем выполнен непрерывный проход всех 13 сцен по отдельному production web bundle без HMR: [browser-clock-fixed-full/results.json](browser-clock-fixed-full/results.json). Проверены autoplay, pause, промежуточное восстановление через меню, продолжение таймлайна после восстановления, ручные шаги, формула, отдельный возврат к ручному кадру с сохранённой формулой, повтор после завершения. Во всех 13 сценах точное совпадение пикселей на паузе, после возвращения к промежуточному кадру и после возвращения к ручному кадру. Ошибок JavaScript — 0. Этот проход не выдаётся за проверку EXE; нативное подтверждение новой сборки выполняется следующим этапом.
